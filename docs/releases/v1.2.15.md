# TrainPilot phone 1.2.15 /2722 — Mini Journal sync recovery (candidate)

Paired with Wear **1.2.17 /2724** on draft PR #156.

- Reopening/foregrounding the phone resends the current watch-home snapshot even when its content is unchanged. Routine polling still skips unchanged payloads.
- A watch `requestHome` command requests a fresh, read-only Journal projection. It is acknowledged only after the phone successfully publishes the snapshot; failures retain the command for retry.
- Wear provenance uses the same stable workout identity as the sync protocol (`syncId`, `id`, `workoutId`, then timestamp). Equivalent timestamp precision preserves linkage; measurements belonging to another workout remain excluded.
- The complete UTF-8 DataItem is bounded, so a large accented/custom exercise catalog cannot block Journal transfer. Missing active programs do not prevent saved-history transfer.
- Snapshots advertise phone version and Journal capability to distinguish an outdated phone payload from an empty completed-workout history.

Regression example: the same saved quick workout has **4 kcal measured on Wear**, while its separate Health Connect interval has **1 active / 2 total kcal**. The default Journal view shows the Wear measurement without adding or converting these sources.

Required checks: full phone runtime regressions, all six Chromium UI shards, Android/JVM tests, performance budgets, signed APK and signer continuity. Physical paired Watch7/phone acceptance remains pending; this candidate is not promoted to main.
